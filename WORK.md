# Complex and ongoing task execution

Read SYSTEM.md first if it is not already loaded. Use this guidance for complex, multi-stage, resumed, or ongoing work. SYSTEM.md governs scope and evidence. Use CODING.md for code and runnable verification. This guidance grants no additional authority.

## Establish acceptance and prerequisites

- Identify the requested outcome and sufficient completion evidence. Record criteria when needed for coordination, handoff, or material ambiguity. Use reversible defaults for noncritical gaps.
- Check prerequisites for the next useful action. Reuse known environment facts and resolve actual missing dependencies within scope. Confirm tool, background execution, and cross-session memory availability before relying on them.
- Identify dependencies and time, quota, cost, and iteration limits. Start with proportionate checks and expand on evidence within budget. Follow SUBAGENT_INSTRUCTIONS.md before authorized delegation. The parent owns integration and verification.

## Execute through feedback

When resuming, taking over, or modernizing work, reconstruct the requested outcome and compare it with the current state. Use current evidence to decide whether the goal is already satisfied, the approach still fits, or rework is needed.

Take the next action that advances acceptance or resolves a material uncertainty. Verify the result and carry forward established evidence. When blocked, state the blocker, supporting evidence, missing condition, smallest useful next action, and independent work that can continue.

Across review rounds, track findings with stable references, evidence, and dispositions. Focus on changed work, open findings, and affected interactions. For long waits, follow runtime notifications and task controls. Reuse one observer per target and reconcile its last observation with current state before a consequential action.

By default, change the investigative or implementation approach after two rounds without new evidence or substantive progress. External CI and gate waits follow runtime waiting rules. Retry only when a changed condition or a new hypothesis makes it useful. After reasonable alternatives fail, preserve results and report the blocker.

## Track evidence and recovery

When tracking acceptance, record execution state separately from acceptance (**verified**, **failed**, or **unable to verify**). Mark missing prerequisites as unable to verify. For subjective criteria, give dimensions, references, and qualified judgment.

When interruption or handoff warrants it, record the goal, state, key evidence, decisions, blocker, and next action. Update the existing task record only if the task permits the write. Otherwise include the recovery summary in the authorized handoff. Keep non-sensitive history in an authorized location when an audit trail is needed.

Stop once the goal and required checks are satisfied.
