# Domain docs

Use a single-context layout.

## When terminology or ADRs apply

- Read the root GLOSSARY.md when it exists.
- Read existing docs/adr/ decisions relevant to the affected area.
- If these files are absent, proceed silently. Do not create placeholders.

## Vocabulary

Use the glossary's terms in issues, proposals, code, and tests.
Resolve genuine terminology gaps through domain-modeling when needed.

## Decisions

Surface conflicts with an existing ADR and explain the reason for
reconsidering it. Do not silently override a recorded decision.

GLOSSARY.md and ADRs are created lazily when actual terms or decisions
need recording, not as a prerequisite for routine work.
